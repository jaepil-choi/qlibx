usage: vqapr run [-h] [--force] [--run-id RUN_ID] spec

Judge a run spec, freeze it, preflight it, and execute the simulation.

The spec names already-registered components by id; it does not redeclare them. Preflight refuses any drift between the spec and what is registered, and the same judgments `vqapr check` makes are made here before the spec is frozen: a run that would fail `check` is refused rather than executed.

`check` is still the cheaper way to see every problem at once -- it collects them, while a run refuses on the first set it finds. Write a starting spec with `vqapr new run-spec --out spec.yaml`, and prove it with `vqapr check spec.yaml`.

positional arguments:
  spec             path to the run spec YAML (write one with `vqapr new run-
                   spec --out`)

options:
  -h, --help       show this help message and exit
  --force          replace this run id's existing run record instead of
                   refusing. Refusing is the default because a repeated run
                   under the same --run-id is far more often a retry than an
                   intended overwrite. This does not remove a published
                   dataset
  --run-id RUN_ID  identity for this run's frozen record (defaults to the
                   spec's filename)

Emit a starting point.

  vqapr new datamodel|strategy <id> --dataset <d>
      writes a component .py that runs as written, plus the .yaml that registers it.
  vqapr new dataset --out <path>
      writes a dataset declaration template with every required key commented.
  vqapr new execution-input --out <path>
      writes the venue-table declaration a run fills against.
  vqapr new agendas --out <path>
      writes the cadences a run fires on, plus the configs that bind roles to them.
  vqapr new run-spec --out <path>
      writes a run spec template with every required key, each one commented.

Nothing is registered by this command. Pass the emitted .yaml to `vqapr register`.

positional arguments:
  {datamodel,strategy,constraint,instruments,dataset,execution-input,agendas,exchange,run-spec}
                        scaffold a component (datamodel/strategy/constraint)
                        or emit a template (instruments/dataset/execution-
                        input/agendas/exchange/run-spec). Component and
                        exchange kinds write TWO files: the .py named by
                        --out, and the .yaml beside it that registers it.
                        Every registrable kind reports the file to hand `vqapr
                        register` as `declaration`; `run-spec` reports
                        `registrable: false` instead, because a run spec is
                        handed to `vqapr run` rather than registered
  component_id          identity of the new component (required for
                        datamodel/strategy, unused for run-spec)

  --dataset DATASET     dataset_id the component reads (required for

  --cap CAP             largest share of the book any one name may be

  --out OUT             output path for the emitted file
