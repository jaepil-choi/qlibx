# 2026-09-03 — 0.3.0 shipped: the convergence campaign, as one breaking release

## What is on develop

`v0.3.0`, tagged on `develop`. Everything the convergence campaign merged
(`docs/refactoring/2026-09-02-the-convergence-campaign.md`, Step 0–7, records `129`–`139`), plus
the `049` measurement that the campaign's last gate owed. Minor bump, not a patch: every step
below breaks a consumer written against `0.2.0a2`, by design (campaign §"이 캠페인에 넣지 않은
것" and design §2.4 — no shape is kept in two spellings for compatibility).

| step | record | what a consumer sees |
|---|---|---|
| 0 | `129` | four unused runtime deps gone (`cvxpy`, `pandas`, `pydantic`; `pytz` kept because duckdb imports it); duckdb progress bar off, so a slow command's JSON envelope parses (`047`) |
| 1 | `130`–`133` | **one author surface.** `vqapr.public.DataModel is vqapr.authoring.DataModel`, and the same for `StrategyModel`, `Constraint`, `ConstraintBounds`, `ConstraintFinding`. Every role declares reads with `inputs()` and is handed a call with `read(alias, field)` / `rows(alias)`; a constraint has two consumers (`project`, `monitor`) and its bounds are `lower_weights` / `upper_weights`. The three scaffolds emit the same import. `strategy_bridge.py` and `agent_first.py` are deleted (`036`, R5, R6, `G011`) |
| 2 | `134` | a declaration document is **one transaction**: all validated, then one lock, one write. A refusal at the k-th item leaves the workspace byte-identical (testbed A3) |
| 3 | `135` | the run record **streams** as occurrences are accepted and carries its types, so reading it back cannot reproduce the tz trap; `show run --table … --limit` filters instead of dumping millions of rows; `store.account_positions` (testbed A4–A6) |
| 4 | `136` | one scan serves every field an alias declares (`046` first half) |
| 5 | `137` | **`grain` is declared on every registration** — `instrument_instant`, `instant`, `rows` — and a registration without one is refused on read. `RowsLookback(n)` is the table's last n instants (panel), `InstantsLookback(n)` is the per-name count and belongs to `grain: rows`; each is refused on the other grain. A panel grain is scanned once per run and sliced per read (`035`, `045`, §17.1.x) |
| 6 | `138` | an agenda is shareable: `strategy_configs` is keyed by strategy, not agenda (`040`) |
| 7 | `139` | **the Run is configuration.** A run is registered (strategies, agendas, instruments, execution input); each strategy's record is its own output with `run.json` naming the execution input and fill declaration (`034`) and the sha256 of every source read (testbed A7); `vqapr rm <kind> <id>` exists (testbed C4) |

Migration for a `0.2.0a2` project is the refusals: register each dataset again with a `grain`,
move `context.window.observations(...)` reads to `call.read(alias, field)` (panel) or
`call.rows(alias)` (rows), rename `bounds.lower/upper` to `lower_weights/upper_weights`, and
register a run before running it. `kwam-enhanced-index/vqapr-enhanced-index-3` is pinned to the
`0.2.0a2` wheel and is that project's to move.

## The measurement `049` owed

Taken on this tree by `experiments/exp_049_the_measurement/` (the consumer-repo harness the
issue pointed at no longer exists, record `136`). Same annual-fundamentals reduction, three
registrations of two generated files, 1,600 instruments × 4 evaluations, anti-join read before
any timing:

| side | registration | wall | per eval | read in callback |
|---|---|---:|---:|---:|
| `rows` | the long file, `grain: rows` | 372.57s | 93.14s | 365.67s |
| `expr` | the **same long file**, `grain: instrument_instant`, items as aggregate expressions | 5.04s | 1.26s | 3.16s |
| `wide` | pre-pivoted file, `grain: instrument_instant` | 2.46s | 0.61s | 0.72s |

Anti-join zero rows both directions on all three pairs; 6,400 rows published by each.
**`rows/expr` 73.9×, `rows/wide` 151.5×.** `expr` is the `049` ruling delivered: the author keeps
the vendor's long table and declares the pivot, and pays the pivot once per run. `049` is closed.

The measurement found two things, filed rather than fixed:

- **`053`** — `InstantsLookback(n)` counts source rows, not instants, on `grain: rows`, the one
  grain it is admitted on. Four instants × three rows, `InstantsLookback(2)` → two rows, one
  instant. The docstring and the refusal text both say instants. And a `rows` grain admits no
  calendar window, so the original long-table model's question is not expressible there.
- **`054`** — 70% of a `rows` read is `Observation` construction, most of it `_copy_values`
  re-checking field names character by character per row (14.6M checks for 159k rows) and
  `pytz` conversions; the scan is 30%. Same shape `044` closed on the other path.
