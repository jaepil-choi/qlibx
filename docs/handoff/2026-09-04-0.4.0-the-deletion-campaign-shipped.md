# 2026-09-04 — 0.4.0 shipped: the deletion campaign, as one breaking release

## What is on develop

`v0.4.0`, tagged on `develop`. Everything the deletion campaign merged
(`docs/refactoring/2026-09-03-the-deletion-campaign.md`, Step 0–7, records `141`–`148`), plus
the owner's ruling on model identity that followed Step 7. Minor bump, not a patch: Step 7
rewrites the run declaration and every consumer written against `0.3.0` moves by hand.

| step | record | what a consumer sees |
|---|---|---|
| 0–1 | `141`, `142` | `InstantsLookback` counts instants on `grain: rows` (`053`); a rows read no longer re-checks field names per row (`054`) |
| 2 | `143` | `PanelWindow.values` is lazy (`061`) |
| B | `144` | the read verbs follow the grain |
| C-1 | `145` | pydantic documents replace the hand-written codec; `valuation_configs` / `monitoring_policies` sections retired |
| 5 | `146` | record tables are parquet chunks, typed |
| 6 | `147` | one loop, four phases (`flow/simulation.py`, `context.py`, `callback.py`, `execution.py`, `valuation.py`) |
| 7 | `148` | **a run declares its sessions and one wall time; a datamodel is a run.** `agendas:`, `strategy_configs:`, `valuation:`, `monitoring:` are gone: a run carries `sessions_from` (or `sessions`), `timezone`, `at`; every model is called every session and decides for itself; the book is valued at the fill instant and monitored right after each commit. `datamodels:` runs write one parquet chunk per session under `.vqapr/materialized/<dataset_id>/` and register the dataset once at the end; `materialize()` and the spec file are deleted. `list/show/rm datamodel`; `new datamodel` emits its run block. `059` closed |
| after 7 | (commit `04549685`) | a strategy's or datamodel's identity folds its sessions' content (role, zone, local instants), not the derived agenda's name, so the same model on the same sessions under two run ids is one identity |

Migration for a `0.3.0` project: delete the four retired sections; on each `runs:` entry replace
`valuation:` / `monitoring:` with `sessions_from: <dataset>` (or `sessions: [...]`), `timezone`
and `at` (the strategies' callback time); drop the per-strategy `agenda:`; rewrite each
materialization spec as a `runs:` entry with `datamodels: {<component>: {dataset_id, value_fields}}`
and run it by id. A 0.3.0 `workspace.yaml` opens (the retired sections are read and dropped); a
run entry in the old shape is refused at open naming the keys it now needs.
