# 032 Declare the Python floor the package actually requires

## Intent

`pyproject.toml` declared `requires-python = ">=3.10,<3.13"`, but eleven modules import `StrEnum`,
which Python added in 3.11. Dependency resolution therefore succeeded on Python 3.10 and the very
first `import qlibx` failed with `ImportError: cannot import name 'StrEnum' from 'enum'`. PRD §1.2
begins its onboarding contract at the moment after `uv add qlibx` succeeds, so a distribution that
installs and then cannot be imported breaks the product promise before any qlibx behavior runs.

The affected modules are `domain.py`, `errors.py`, `onboarding.py`, `account/account.py`,
`analysis/results.py`, `config/project.py`, `data/contracts.py`, `evidence/contracts.py`,
`flow/composition.py`, `operations/strategy.py` and `portfolio/construction.py`.

## Observable outcome

A 3.10 environment now fails at resolution with an actionable message instead of installing a
package that cannot be imported. The published wheel and sdist carry
`Requires-Python: >=3.11,<3.13`, and `README.md` states the requirement so a reader does not have to
infer it from a resolver error.

No runtime behavior changes. This commit makes packaging metadata agree with code that already
required 3.11.

## Responsibilities and flow

- `pyproject.toml` — `requires-python = ">=3.11,<3.13"`; `[tool.ruff] target-version = "py311"`.
- `README.md` — a Python requirement bullet at the top of the summary list.
- `uv.lock` — regenerated by `uv sync`; the lock records `requires-python` and would otherwise
  disagree with the manifest.

Raising the ruff target from `py310` to `py311` activated `UP017` at 27 sites, which were autofixed:
`timezone.utc` became `datetime.UTC` in `src/qlibx/data/store.py`, `src/qlibx/kernel/clock.py` and
five test modules. These are alias substitutions with identical semantics — `datetime.UTC` *is*
`datetime.timezone.utc` — and they do not touch
`tests/test_architecture.py::test_production_source_does_not_read_wall_clock_directly`, which
forbids `.now()` calls rather than timezone references.

## Alternatives and trade-offs

**Raising the floor to `>=3.12`** was rejected. `.python-version` pins 3.12 and all validation runs
there, so 3.12 is the only interpreter actually exercised. But nothing in the source requires 3.12,
and narrowing the supported range beyond what the code needs excludes 3.11 users without a technical
reason. The declared range should describe the code, not the development box.

**Keeping `>=3.10` and removing `StrEnum`** — replacing eleven `StrEnum` declarations with
`class X(str, Enum)` — was rejected. It reaches the same consistency by touching eleven production
modules instead of two metadata lines, changes enum semantics subtly (`StrEnum.__str__` returns the
value; a plain `str, Enum` mixin does not), and would need a 3.10 validation environment that does
not exist here.

**Leaving `target-version = "py310"`** while raising `requires-python` was rejected as a smaller
diff. It would keep ruff linting against an interpreter the package no longer supports and suppress
modernizations that are now always safe.

## Validation

```
.venv/Scripts/python.exe -m pytest tests -q
-> 142 passed in 111.25s

.venv/Scripts/python.exe -m ruff check .
-> All checks passed!

uv sync --cache-dir .uv-cache
-> uv.lock requires-python = ">=3.11, <3.13"
```

Test count is unchanged at 142 by design: this commit alters no behavior, so an unchanged suite is
the evidence. `UP017` was verified clean after the autofix rather than assumed.

## Remaining limitations

- Only 3.12 is exercised by CI and local validation. The `>=3.11` floor is derived from source
  analysis (`StrEnum` is the single 3.11-only construct; a repository-wide search found no use of
  `datetime.UTC` as an import, `Self`, `tomllib`, or `ExceptionGroup` before this commit), not from
  a 3.11 test run.
- `<3.13` remains an untested upper bound inherited from the previous declaration; it was not
  revisited here.
