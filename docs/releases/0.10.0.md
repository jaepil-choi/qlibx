# vqapr 0.10.0 — breaking

Released 2026-09-10 from `develop`. Records `201`–`214`, the two-clocks campaign
(`docs/refactoring/2026-09-09-the-two-clocks-campaign.md`); the contract it implements is
`docs/design/two-clocks-and-the-wiring-table.md`, now absorbed into the PRD and the architecture.

**0.9.0 was never released.** `0.9.0.dev0` and `0.9.0.dev1` were development builds installed into
testbeds from `dist/`; their notes (`docs/releases/0.9.0.dev1.md`) describe the layering campaign
(records `190`–`198`) and the tenth skill, `report-issue-dev`. Both ship here unchanged. This file
is about what moved on top of them.

The campaign started from one sentence the previous tree could not express — *a strategy that
decides every minute and fills every minute* — and ended by rewiring what an agent or a script can
see: how a run is declared, when it is called, when it fills, what watches its book, what a venue is
handed, and every run identity.

## 1. A run is one model, and it names what it writes (records `201`, `202`)

**`strategies:` and `datamodels:` are singular.** A run executes one model:

```yaml
runs:
  my-alpha:
    writes: my-alpha-weights          # required: the dataset this run puts in the project
    strategy:
      component: my-alpha
    ...
```

A workspace written before this release still opens: the old `strategies: {id: {...}}` mapping is
read when it names one model and refused by name when it names two. Three models on one cadence are
three runs — two runs declaring the same inputs freeze identically, so the comparison is exactly as
sound as it was inside one run, and it now holds across runs made on different days.

**`writes:` is required, and it is a name only.** The schema is already declared on the consumer
side. A strategy run publishes its allocation (`vqapr.weight`) under that name; a datamodel run
publishes its output. A name another run or a person already registered is refused
(`run.output_registered`) at `check` and at `run`; re-running a run over its own previous output is
refused without `--force`, exactly as its record is.

**`vqapr run` takes several run ids and `--jobs` spreads runs**, not members. `--strategy` is gone.
`datamodel.output_registered` is gone; `run.output_registered` covers both kinds.

## 2. Two clocks, one declared (records `204`, `206`, `207`)

**`sessions`, `sessions_from` and `at` moved into `agenda:`**, refused by name if they are still
there:

```yaml
    timezone: Asia/Seoul
    agenda:
      every: 1d          # 1d | 2d | 1w | 1M — trading days, paired with `at`
      at: "15:29"        #   one wall time or a list
    # agenda:
    #   every: 5m        # 1m | 5m | 1h — instants inside each day, paired with from/to
    #   from: "09:00"
    #   to: "15:20"
```

The days are not typed. A strategy run's trading days are the days its execution dataset has rows
for; a datamodel run names the dataset whose days count with `agenda.days_from`. Denser data adds
fill instants, never decision days. Occurrence ids are `{agenda}-{date}T{HHMM}`.

**There is no valuation or monitoring schedule any more, because there is a market clock.** Every
instant the execution dataset has inside the run is one: at each, in this fixed order, the pending
decision whose target it is fills, the book is valued at the venue's price, and the run's declared
Compliance rules observe the committed book. A decision scheduled at the same instant runs last and
sees the valued book. Consequences you will notice:

- **The book is valued at every execution instant**, whether or not anything traded and whether or
  not the strategy was called. A daily table gives a daily NAV series under a monthly strategy; a
  one-minute table gives one point per minute. Densifying the table multiplies `vqapr.account` rows
  and leaves decisions and fills unchanged.
- **`Hold` schedules nothing.** It commits model state and leaves the pending intent alone; the next
  market instant values the book.
- Run identities no longer fold agenda names or valuation settings; they fold the expanded agenda
  and the market clock's source.

## 3. A decision fills at the first market instant after it (record `205`)

`fill:` lost `selector`, `timezone` and `trade_price`, refused by name. The default needs no
declaration: a decision fills at the **first execution instant after it**. Three optional handles
narrow it:

```yaml
    execution:
      dataset: krx-daily
      trade_price: close          # moved here from fill:, beside the dataset it names a field of
      fill:                       # optional
        at: "15:30"               # keep only instants at this wall time (the run's timezone)
        # after: 10m              # minimum elapsed time after the decision
        # within: 1d              # fail the decision if no instant lies inside this gap
```

`SAME_DAY` / `NEXT_ELIGIBLE` and `local_time` are gone: *"roll to the next day if missed"* is
`within`, and *"today's 15:20 or tomorrow's"* is answered by "first after the decision". Leave `fill:`
out on a one-minute table and a strategy declared `every: 1m` fills every minute (`AC-1`).
`FillConvention` and `FillSelector` left `vqapr.public`; `FillRule` is what a frozen run carries.

## 4. `Constraint` is gone; `Compliance` is in (records `208`, `209`)

**A constraint is not an extension point.** The box a strategy builds inside is the strategy's
discretion, so the framework guarantees nothing about it and ships it as a kit instead:

```python
from vqapr.public import intersect, no_short, single_name_cap

lower, upper = intersect(no_short(names), single_name_cap(names, benchmark, Decimal("0.10")))
```

Pure functions, `(lower, upper)` boxes out, called inside `decide()`. A strategy that caps against
the index **subscribes to the benchmark weights itself** — the dependency used to hide inside the
constraint's requirements. The strategy's own diagnostic tables are where "how much did the cap
bind" is recorded now; the framework no longer writes before/after per constraint.

**What watches the committed book is a `Compliance` rule, declared on the run beside the venue:**

```yaml
    exchange: krx
    compliance: [no-short, single-name-cap]
```

`constraints:` on a strategy entry is refused by name. A rule implements one method,
`observe(call, account) -> ComplianceFinding`, subscribes to its own data (`inputs()`), keeps its own
`memory` (violations are counted, and counting remembers), carries its own parameters and a
`tolerance` — **it does not inherit the strategy's cap or benchmark**, because a watcher that
inherits the target's goal is self-grading. It runs at every market instant right after valuation
and never touches the account. A residue inside its tolerance (integer rounding, for instance) is not
a breach.

- `vqapr new compliance <id> --cap 0.1` scaffolds one; `register_compliance` registers it; the
  built-ins are `no-short` and `single-name-cap` (`SHIPPED_COMPLIANCE`, `shipped_compliance_path`).
- `vqapr.monitoring` rows name their `rule` (the column was `constraint`); `strategy.json` carries
  `compliance` (was `constraints`) and `contract_report` is keyed by `rule_id`.
- Refusal codes renamed: `constraint.identity_mismatch` → `compliance.identity_mismatch`,
  `component.constraint_id_mismatch` → `component.compliance_id_mismatch`.
- The skill `make-constraint` is now `make-compliance`; `make-strategy` documents the kit.
- Datamodel runs refuse `compliance:` — there is no book to watch.

## 5. A strategy run needs an instrument roster (record `203`)

The venue must know what every ordered id *is* before it can size or charge it. A strategy run
declares `instruments:`; a project that has declared none is refused at `check` and at `run`
(`roster.absent`, 412). The roster need not cover the whole execution table — only what gets
ordered — and an order for an id it never described fails the run at the fill instant
(`instrument.undeclared`), naming **every** undeclared id at once rather than the first.
`register_instruments` (export and register in one call) joined `vqapr.public`; the shipped sample
declares its roster when it materializes.

## 6. The venue is handed a dictionary and keeps its own settings (record `210`)

`ExecutionCall` gained two fields: `instruments`, the whole registered roster, and `rules`, bound to
it. A venue reads identity (`kind`, currency) from the dictionary rather than guessing, and a rules
view bound to a different dictionary is refused. Fill fields are unchanged.

**A venue declares `settings`** — a strict-JSON mapping whose schema is the venue's own. They are
part of the run's identity and of the record (`strategy.json` gained
`exchange: {component_id, fingerprint, settings}`), so the same venue with a different setting is a
different run (`AC-11`). Settings that are not portable JSON are refused at load
(`component.execution_profile_invalid`).

```python
KrxExchange(listings_or_ids, exchange_id="krx", *,
            commission_rate="0.0003", sale_tax_rate="0.002", price_limits=None)
```

`KrxSettings` is the KRX schema; `KRX_NOT_MODELLED` is data where the docstring used to say
"implemented / not implemented". `AcademicExchange.settings` is fixed
(`{profile: academic, costs: none, partial_fills: never}`). `vqapr new exchange` emits the new
constructor.

## 7. The account is an append-only ledger (records `211`, `212`)

`Account` has two doors, `append(entries)` and `mark(marks)`, and `AccountState` is
`(snapshot, marks, ledger)` — the fold of one shape of entry, `LedgerEntry(at, Δcash, Δpositions,
origin, detail)`, with `origin == "fill"` the only origin today. `fill_history`, `mark_history` and
`JournalEntry` are gone. Nothing in the tables changed: the record digest of every showcase is
byte-identical to the pre-campaign baseline.

Two defects fell out of the rewrite and are fixed: a run that died mid-way used to leave **no**
`vqapr.fill` table (rows were staged only at the end; they now stream per commit, and folding a dead
run's fills reproduces its last `vqapr.account` row — `AC-12`), and a run executed from a stored
definition never published its `writes` dataset (record `210`).

## 8. The wiring table is code (records `213`, `214`)

Design §4's table — which clock each role is called on, what it is handed, who receives its answer —
is data in `vqapr.domain.wiring`, and the authoring base grew two names: `Part` (declares its own
clock: `DataModel`, `StrategyModel`) and `Tool` (attaches to the market clock: `Exchange`,
`Compliance`). Both are in `vqapr.public`. A fifth row, `Accrual` — dividends, borrow, funding —
is reserved with no implementation. Internal packages moved (`flow/strategy` and `flow/datamodel`
became `flow/run`); module paths are not a contract.

## 9. `vqapr.public` — what moved

Removed (10): `Constraint`, `ConstraintBounds`, `ConstraintFinding`, `ConstraintReport`,
`ConstraintSet`, `FillConvention`, `FillSelector`, `SHIPPED_CONSTRAINTS`, `register_constraint`,
`shipped_constraint_path`.

Added (17): `Compliance`, `ComplianceCall`, `ComplianceFinding`, `ComplianceReport`,
`ComplianceSet`, `FillRule`, `KrxSettings`, `Part`, `RunAgenda`, `SHIPPED_COMPLIANCE`, `Tool`,
`intersect`, `no_short`, `register_compliance`, `register_instruments`, `shipped_compliance_path`,
`single_name_cap`.

## 10. Every run identity changes

Identities fold the expanded agenda, the market clock's source, the fill rule, the roster, the
venue's fingerprint **and settings**, the compliance declaration and `writes`. Re-run rather than
expecting a 0.9.x record to match.

## Also in this release (not breaking)

- The PRD and the architecture absorbed the design: §3 of each is written around the two clocks,
  PRD §7 and architecture §5.7 around the kit and Compliance, architecture §10 re-measured.
- `vqapr run --help` says what a run is now (one model; several ids run several runs).
- Skill text across `run-backtest`, `make-strategy`, `make-datamodel`, `make-exchange`,
  `inspect-workspace`, `analyze-result`, `introduce-vqapr` and `register-dataset` follows the new
  declarations. `skill install` will report those files `outdated` on a 0.8.0 or 0.9.0.dev1 install
  and update them.

## Migrating a 0.9.0.dev1 (or 0.8.0) tree

1. **Run declarations.** Rename `strategies:`/`datamodels:` to `strategy:`/`datamodel:` with a
   `component:` key (or leave the old mapping if it names one model). Add `writes:`. Replace
   `sessions`/`sessions_from`/`at` with an `agenda:` block. Move `trade_price` from `fill:` to
   `execution:`; delete `selector` and `timezone`; add `fill: {at: ...}` only if you want a wall
   time. Each of these is refused by name with the replacement spelled out.
2. **Constraints.** Delete `constraints:` from strategy entries. Inside `decide()`, build the box
   with `no_short` / `single_name_cap` / `intersect` and subscribe to the benchmark dataset the cap
   needs. Declare `compliance: [no-short, single-name-cap]` on the run if the book should be
   watched. A project-local `Constraint` becomes a `Compliance` with one `observe`; `vqapr new
   compliance` shows the shape.
3. **Instruments.** Register a roster (`vqapr new instruments <ids...>`, then `register`) for every
   strategy run.
4. **Custom venues.** Read `call.instruments` and `call.rules`; declare `settings` if the venue has
   any switches. `KrxExchange` subclasses pass `commission_rate`, `sale_tax_rate`, `price_limits`
   as keywords.
5. **Anything reading `vqapr.monitoring`.** The column is `rule`. Anything reading `strategy.json`:
   `compliance` and `exchange`.
6. **Run identities.** Re-run.
