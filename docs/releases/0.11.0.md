# vqapr 0.11.0 — breaking

Released 2026-09-10 from `develop`. Started the same day from the seven reports the enhanced-index testbed
(`kwam-enhanced-index/vqapr-enhanced-index-3`) filed against `0.9.0.dev1` on 2026-09-09. On triage
they became `docs/issues/089`–`095`; the seventh (`095`, the roster judgment) had already been closed
by record `203` in 0.10.0 and went straight to the archive. The other six are closed by records
`215`–`220`, one each.

Records `215`–`220` close those reports; records `221`–`229` are the one-loop campaign
(`docs/refactoring/2026-09-10-the-one-loop-campaign.md`), merged the same day. Each section names
the report it closes and the record. Two changes are breaking; the migration steps are at the end.

## 1. A model's opening memory is `{}` (record `215`, closes `089`) — breaking

`self.memory` is an empty mapping on a run's first callback unless the run declares
`initial_model_memory`. It was `None`, so the `make-strategy` reference's own example
(`self.memory.setdefault("sessions", 0)`) raised `AttributeError` on session one of every run, and
`check` could not see it. A declared `initial_model_memory: null` reads as the same `{}`.

**Breaking because the opening memory is folded into every run identity.** A 0.10.0 record of a run
that declared no opening memory will not match the identity 0.11.0 computes for the same
declaration, and a re-run under the same run id is refused as a changed configuration.

## 2. The retry is `--force`, and the refusal says `datamodel` (record `216`, closes `090`)

Running a run again with its component unchanged, after `rm dataset`, is refused as
**`record.exists`, 409, stage `record`** — beside `record.live` — naming the model's kind ("a
datamodel record is written once per run and fingerprint") and `vqapr run <id> --force`. It was a
400 `argument.value_invalid` that said "edit the strategy" to a datamodel run and carried a
`FileExistsError` traceback.

`make-datamodel`'s "Retrying" section now says what the code does: **`vqapr run <id> --force` is
the retry** (record and dataset replaced together); `rm dataset` drops an output. The old code name
`datamodel.output_registered` in three skill files is `run.output_registered`, as it has been since
0.10.0.

## 3. A dataset names the record that wrote it (record `217`, closes `091`)

`show dataset` and `list datasets` carry **`produced_by_record`** — `<component_id>@<fp8>`, the ref
`list datamodels` and `rm datamodel` address — beside `produced_by` (the run id). Several records
can write one dataset id in turn; now the dataset says which version's rows it holds.

**`vqapr check <run-id>` reports `run.output_stale` (412)** when the run's registered output was
written by a component version other than the one registered now, naming both refs; the fix is
`vqapr run <id> --force`. `run` itself does not raise it: without `--force` it refuses its own
standing output anyway (`run.output_registered`), and `--force` is the repair.

A dataset written before this release has no `produced_by_record` and is not judged stale until it
is rewritten once.

## 4. The box kit rounds inward onto the grid (record `218`, closes `092`)

`single_name_cap` and `intersect` return bounds on the canonical `1E-12` grid, ceilings rounded
down and floors up, so a benchmark weight read from a DOUBLE field becomes a bound `optimize`
accepts. It refused the kit's own output (exponent −16), and the caller had to choose a rounding
direction on a value it did not compute — the wrong direction being a mandate breach nothing
reports. `optimize`'s refusal for a fine bound now names the kit and the two directions.

## 5. `show dataset` shows the projection (record `219`, closes `093`)

`items` holds the **declared fields with the values a model receives**, read through the same
`projection_relation` the read path uses; it was the source file's `SELECT *`, which for an
aggregated registration showed none of the declared fields on rows the projection excludes. New
keys: `items_are` (`"projection"` or `"source"`) and `source_rows_total` (always the file's count);
`rows_total` counts what `items` pages over. New flag: `show dataset <id> --source` for the file's
own rows. For an aggregated registration the projected head evaluates the whole grouping — a full
pass over a large file, which is the cost of confirming the reduction rule.

## 6. A missing source is a 404, and the skills say what 502 means (record `220`, closes `094`)

A component `path` that resolves to nothing is **`component.source_missing`, 404**, at registration
and at load; the fix says a relative `path` resolves against the declaration file's own directory.
It was a 503, which the skills class as "retry unchanged". A file that exists but cannot be read
stays `component.source_unreadable`, 503.

The skills were wrong about 502, not the code: `Status.CRASHED` (502) has always meant *your own
component raised*, with `cause.origin: "user"` and `cause.where` at your line. `report-issue-dev`'s
decision table, its reference, and the footers of nine other skills said "500 or 502 is a vqapr
defect"; they now say 500 is, 502 is yours to fix, 503 is the machine.

## 7. `Compliance.observe` takes one call (record `229`) — breaking

`observe(self, call, account)` is `observe(self, call)`, and the account is `call.account`. A
role's Call is the whole of its authority (the one-loop campaign, L5): the wiring table already
listed the committed account as a View Compliance receives, and the signature now agrees. The
shipped rules, the scaffold and the `make-compliance` skill are updated; the conformance check
refuses the old arity at registration.

## Also in this release (not breaking)

- **A minute-grained market clock costs a third of what it did, and a run's memory no longer grows
  with it** (the one-loop campaign, records `221`-`228`). Measured on 3,000 names over one day of
  minutes (`experiments/exp_221_the_market_clock_cost/`): 117 s to 34 s; `Mark` objects retained
  by a finished run 1,167,000 to 3,000. Rows travel as columns from the recorder to the record
  (`221`), the execution table is read ahead along the market clock (`222`), the framework's own
  views prove nothing twice (`223`), and evidence keeps summaries rather than every mark (`224`).
  `sequence` on every recorded row is now the run's one order rather than a per-callback index
  (`225`); readers that sorted by it within a callback see the same order.
- **One loop walks both kinds of run** (`226`-`228`): a market-clock instant is a fold over five
  stages of one shape, `RunLoop` walks a strategy or a datamodel with the same code, and the two
  members are run through one lifecycle. No user-visible change.

- `vqapr run --help` describes `--force` for both kinds and says it replaces the published dataset
  too.
- `inspect-workspace`, `make-datamodel`, `register-dataset` and `make-compliance` describe
  `produced_by_record`, `run.output_stale`, `items_are` and the kit's rounding. `skill install`
  will report these files `outdated` on a 0.10.0 install and update them.
- Open follow-ups recorded, not done: `vqapr rm` has no `instruments` kind (a roster can be
  replaced, not withdrawn — from `095`); a typed refusal raised by a package helper inside a user
  callback is classified 500 by frame origin and should be a 422 (from `092`/`094`).

## Migrating a 0.10.0 tree

3. **Compliance rules.** Change `def observe(self, call, account)` to `def observe(self, call)`
   and read the account as `call.account`. `vqapr check` refuses the old shape.

1. **Run identities.** Re-run, or `vqapr rm run <id>` the 0.10.0 records first. Runs that declared
   `initial_model_memory` explicitly are unaffected.
2. **Strategies that guarded `self.memory or {}`.** The guard is harmless and may stay.
3. **Scripts that parsed `show dataset`.** `items` is the projection now; pass `--source` to get
   what you had. `rows_total` counts projected rows; read `source_rows_total` for the file's.
4. **Scripts that matched `argument.value_invalid` on a repeated run.** Match `record.exists`
   (409, stage `record`).
5. **Datasets you want judged for staleness.** Rewrite each once with `vqapr run <id> --force` so it
   carries `produced_by_record`.

## Validation

- `test_all` (`uv run python -m pytest tests/ -q -m ""`, the full suite): **1,696 passed** in 180 s on the
  stamped tree. `uv run ruff check src/`: clean. `uv run python -m pyright`: 0 errors.
- All nine showcases exit 0 on the stamped tree, `show_003` (reads the private `data/DW` warehouse)
  included; their `VERIFIED_AGAINST` is `vqapr-0.11.0` as of 2026-09-10.
- `scripts/showcase_record_digest.py --check`: **83/83** record entries identical to the baseline
  (`tests/showcases/baseline-record-digest.json`). The baseline was re-recorded once during the
  campaign, at record `225`, where the `sequence` column's values changed by design; every other
  table is row-for-row what 0.10.0 wrote. The digest masks 64-hex hashes since `221`, so a checkout
  elsewhere compares equal too.
- `_shipped.json`: the 18 skill files that changed since 0.10.0 are recorded under `0.11.0`; the one
  hash a dev build carried and superseded was dropped. `release_check` passes.
- Built with `uv build` from the stamped tree: `vqapr-0.11.0-py3-none-any.whl` and the sdist.
- Performance, measured (`experiments/exp_221_the_market_clock_cost/`): 3,000 names on a minute
  table, one day, 117.4 s at 0.10.0 → 34 s at 0.11.0 (this machine varies ±25% run to run; the
  smaller of two runs); `Mark` objects retained by a finished run 1,167,000 → 3,000.
