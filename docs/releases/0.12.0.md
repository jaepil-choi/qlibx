# vqapr 0.12.0 — breaking

Released 2026-09-10 from `develop`. The one-door campaign
(`docs/refactoring/2026-09-10-the-one-door-campaign.md`, records `231`–`234`): three things the
owner found reading the 0.11.0 spine traces (`docs/issues/archive/095`–`097`), fixed in the order
L → P → V on `redesign/one-door`. One change is breaking; the migration steps are at the end.

## 1. A physical read is measured once, at one door (record `234`, closes `095`) — breaking

`data/validation.py` is the one module that measures a file. `verify_source` runs at registration
— schema, key, span, values, the execution prices, and a sha256 of the bytes — and the registration
keeps what it measured: **`source_digest`** and, for a table with an execution role,
**`execution_prices`** (the price fields that are finite and positive on every tradable row).
Every later reader — `check`, preflight, `run` — asks the workspace for identity and never
re-scans: the digest is compared once per workspace object, and nothing else is read.

- **`dataset.source_changed` (412, stage `freeze`)**: the file's bytes differ from the ones
  registration measured. Fix: `vqapr register` the same declaration again — registering the same
  declaration on changed bytes replaces the measured half (span, digest, prices) under the same id.
- **`dataset.unverified` (412)**: the registration carries no digest, which is what every dataset
  registered by 0.11.0 or earlier looks like. Fix: register it again.
- **`execution.price_not_positive`** at preflight: the run's `trade_price` names a field that was
  not positive on every tradable row when the table was registered. It replaces the scan
  `execution_table.price_invalid` made at every `check` and `run`.
- The `execution_table.*` codes (`field_type`, `key_null`, `key_duplicate`, `price_invalid`,
  `price_type`) are gone; the same defects are the dataset's own `dataset.*` codes at registration.
  The roster read returns a `Diagnosis` too: `roster.table_missing`, `roster.table_invalid`.

**Breaking because a registration written before this release has no digest.** It opens, lists
and shows as before; a run that reads it is refused as `dataset.unverified` until it is registered
again. `validate_execution_table` and its three diagnoses are deleted from
`exchange/execution_table.py`.

## 2. A window is a matrix (records `232`, `233`, close `096`)

`PanelWindow.matrix(field)` returns the window as a `numpy` array of shape `(instants, names)`,
float64, NaN where a name has no row at an instant; `window.instruments` is its column order. A
`Panel` holds one name-major Arrow array per field instead of one Python column per name, and
`counts`, `current` and `latest` are vectorised. Measured on 3,000 names
(`experiments/exp_231_the_panel_read_cost/`): building a window 10.7 → 1.2 ms, `counts`
3.1 → 0.2 ms, the sample strategy's `decide` 8.8 → 1.5 ms. `values` and `series` are unchanged for
code that reads one name's series; `matrix()` refuses a non-numeric field by name.

The shipped sample strategy (`reversal_5d`), the `vqapr new strategy` scaffold and the panel
flavours of the `vqapr new datamodel` scaffold compute on the matrix; `Decimal` appears only at the
`Rebalance` boundary. `make-strategy` and `make-datamodel` describe `matrix()` in their
`reading-inputs` references. `numpy` is a declared dependency.

## 3. One loop class (record `231`, closes `097`)

The abstract `EventLoop` had one subclass. `RunLoop.run` is the walk; `strategy_loop` and
`datamodel_loop` are functions that assemble one. `flow/engine/loop.py` keeps the event types only.
Not part of `vqapr.public`; no user-visible change.

## Also in this release

- `vqapr check` on the sample door reads no file content (a test counts the scan kernels at zero).
- Two skill reference files changed (`make-strategy` and `make-datamodel`, `reading-inputs.md`);
  `skill install` will report them `outdated` on a 0.11.0 install and update them.

## Migrating a 0.11.0 tree

1. **Every registered dataset.** Run `vqapr register <your declaration file>` once more. The
   declarations do not change; registration measures the digest and the execution prices and
   stores them. Until then a run or `check` that reads the dataset says `dataset.unverified`.
2. **Scripts that matched `execution_table.*`.** Match `dataset.*` at registration and
   `execution.price_not_positive` at preflight.
3. **Strategies that loop over `window.instruments` reading `values[name]`.** They still work.
   `window.matrix(field)` is the faster spelling; the scaffold shows it.
