# vqapr 0.14.2 — three testbed reports closed: a fix that names a real command, a refusal that states the grammar, and `--limit 0` that returns none

Released 2026-09-10 from `develop`. Three records, `243`–`245`, each closing one of the three
untriaged testbed reports of 2026-09-10 (`docs/issues/report-2026-09-10-*`). One behaviour
changes: `--limit 0` now returns zero rows instead of every row (record `245`; migration below).
No registered document or record changes shape; the `check`/`run` envelopes change in the wording of
two `fix` and one `observed` field only (record `243`).

## `dataset.unverified` names the command that exists (record `243`)

A dataset a datamodel run published through its `writes` has no declaration file, so the refusal a
0.12.0 migration reached -- *"register dataset 'alpha-beta-001-values' again"* -- named a command
that does not exist for it, and the reporter spent half an hour establishing that. The registration
already knows what published it (`produced_by`). The two refusals in `require_verified` now say:

```
observed: dataset 'alpha-beta-001-values' was published by run 'alpha-beta-001' before the measurement existed
fix:      publish dataset 'alpha-beta-001-values' again -- the command is `vqapr run alpha-beta-001 --force`
```

and, for a declared dataset, *"register dataset 'X' again -- the command is `vqapr register <its
declaration file>`"*. `retry_precondition` carries the same command. Codes, statuses and `key_path`
are unchanged. The 0.12.0 migration note gained the line it lacked: a run-published dataset is
published again by running its producer with `--force`, in dependency order.

## The `every` refusal states the grammar (record `244`)

`every: 1y` was refused with *"a count and a unit such as 1d, 1w, 1M, 5m or 1h"*, which beside a
refused `1y` read as the closed set of accepted values; the reporter concluded a yearly cadence could
not be declared and moved the schedule into the model. The refusal now states the grammar -- the
count is any positive integer; the unit is `d`, `w` or `M` for trading days or `m`, `h` for instants
inside a day -- and a `y`/`Y` unit is told *"there is no year unit, a yearly cadence is 12M"*. The
run-backtest skill (`SKILL.md`, `references/run-declaration.md`) and the make-datamodel reference
say the same: the count is free, `3M` is quarterly, `12M` yearly counted from the run's `start`.
No year unit is added.

## `--limit 0` returns no rows (record `245`)

`vqapr show dataset <id> --limit 0` on a 430 MB, 8.7-million-row source did not return in five
minutes and once exhausted the machine's memory. `0` meant "every row" since record `077`, and
`show dataset` read every row into Python dicts before answering. A count is a count: `--limit N`
returns at most N rows and `0` returns none, for `show dataset` and for `show strategy --table`
alike. On a 4.2-million-row synthetic source `--limit 0` answers in 0.86 s where the old path took
100 s and 1.78 GB of heap. The envelope's `rows_total`, `matched` and `returned` are unchanged.

## Migrating a 0.14.1 tree

1. **Callers that read a whole table with `--limit 0`.** Ask for `rows_total` rows instead -- the
   first call reports it. The three skill files that taught `--limit 0` (`analyze-result`,
   `inspect-workspace`, `introduce-vqapr`) are updated; `skill install` reports them `outdated` on
   a 0.14.1 install and updates them, with the two run-backtest files and the make-datamodel
   reference from record `244`.
2. **Scripts matching the text of `dataset.unverified` / `dataset.source_changed`.** Match the
   code, not the `fix`; the code and status are unchanged.
