# vqapr 0.15.0 — a record that reads back as numbers, `vqapr export`, a scaffold that shows every piece

Released 2026-09-11 from `develop`, tagged `v0.15.0`. The 2026-09-11 incremental and demo testbed
reports (0.14.4 wheel), closed by records `258`–`263` on `develop` and by the one-reading campaign,
records `264`–`267` (`docs/refactoring/2026-09-11-the-one-reading-campaign.md`). A minor version:
a new command, and three changes an existing caller can notice (see **Migrating**).

## `vqapr export` writes one strategy record as files (record `266`)

```bash
vqapr export <run-id>/<strategy-id>@<fp8> --out outputs/
```

`nav.csv` (one row per valuation, the series `strategy_report` measures, with the local `date`),
`holdings.csv`, `fills.csv`, `weights.csv`, `monitoring.csv` when the run declared a rule,
`tables/<t>.csv` for each table the strategy formed, and `report.json`. Every number is exact decimal
text, never through a float. A file an earlier export left is refused unless `--force`. Nothing is
joined: a strategy's own log against fill prices is the author's question, asked of `fills.csv`.
Three testbed agents each wrote this exporter by hand, and each broke on the way.

## A record's numbers read back as numbers (record `264`)

`vqapr.fill`'s quantities, price, cash, commission and tax and `vqapr.weight.weight` were written
as text, so `read_strategy_table` returned `"15900.0"` for a price while `nav` beside it came back a
`Decimal`. They are recorded as numbers now, and a record written before reads back the same: the
reader restores those package columns by name.

## One address for a record (record `265`)

The Python readers and `strategy_report` take the store as a `str` or a `Path`, and a strategy in
the form the CLI writes it: `strategy_report(".vqapr", "<run-id>/<strategy-id>@<fp8>")`.

## The strategy scaffold shows every piece (record `267`)

`vqapr new strategy` still emits a file that runs as written, and it now shows where each piece an
author reaches for goes: a table of its own (`tables()` and `self.recorder.append`, a `decisions`
log of entries and exits), state across callbacks (`self.memory`), a second dataset and the
`.current()` read of one value per name (commented), and that a fill's price and quantity are read
from `vqapr.fill` afterwards — a fill comes after its callback, and no callback follows the last
one. `call.recorder` now says `self.recorder`. There is no `--recipe` option: one scaffold, labelled.

## Records `258`–`263`

- The skills install at the workspace root, the root every command and the stale-skill note read
  (`258`); `--into` names another directory.
- A decision with no fill is refused once per cause, with the repair that cause needs — a `within`
  shorter than the longest wait, or an `end` before the last decision's fill (`259`).
- `Rebalance.of` takes a zero weight as "hold none of this name", as `Rebalance.signed` does (`260`).
- `vqapr.fill` records `sized_quantity`, what a buy sized to before the planner cut it to the cash
  (`261`); beside `requested_quantity`, the KRX cut is visible in the record.
- A declaration reads YAML 1.2 booleans, so an unquoted `on: last` is the key `on` (`262`).
- Windows installs get `tzdata`, and a missing zone database is named as such (`263`).

## Migrating a 0.14.4 tree

- **Reading a record from Python:** the fill and weight numbers above are `Decimal`, for old and new
  records alike. `Decimal(x)`, arithmetic and `.astype(float)` keep working; code that treated them
  as strings — concatenation, `json.dumps` without a `default` — must change. `vqapr show strategy
  --table` JSON is unchanged (a `Decimal` is encoded as the same text).
- **A workspace below a git root** (`258`): its skills now install in the workspace. The old copy at
  the git root is not removed for you: `vqapr skill remove --into <git root>`.
- **A declaration** (`262`): `yes`, `no`, `on` and `off` are words, not booleans — write `true` and
  `false`. The declaration schema has no field written that way.
- **A strategy scaffolded from 0.15.0** writes a `decisions` table; delete `tables()` and its log
  lines if you do not want it. A `decide()` called by hand, outside a run, needs what a run gives it:
  `memory = {}` and an `InvocationRecorder` for its tables.
- A record written by 0.15.0 has a `sized_quantity` column an older vqapr reads as an unknown column.
