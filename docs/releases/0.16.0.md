# vqapr 0.16.0 — the tree follows the loop, one author surface, and the loop speaks discrete-event simulation

Released 2026-09-12 from `develop`, tagged `v0.16.0`. The concept-tree campaign, records `268`–`279`
(`docs/refactoring/2026-09-12-the-concept-tree-campaign.md`). A minor version, and a **breaking** one:
the run declaration's `agenda:` key, the author import, a Call's time and a run record's schema all
change at once, so a 0.15.0 workspace is registered again and its runs are run again (see
**Migrating**). What a run computes does not change.

## The package is laid out by concept (records `268`–`277`)

`src/vqapr/` was cut by import altitude; it is cut by concept now, and a file is named for what it
holds. The loop is the same one — data in, the strategy decides, the exchange fills, the account
records and values, and the strategy sees the account next time — and every package is one step of it
or one thing it passes:

| package | what it holds |
|---|---|
| `domain/` | the values and the Account aggregate, one concept per module (`account`, `fill`, `order`, `intent`, `listing`, `schedule`, `valuation`, …) |
| `data/` · `record/` | every read (dataset, panel, window, verification, execution table) · what a run leaves behind |
| `signals/` · `portfolio/` | transforms and signal evaluation · weighting, optimisation, netting |
| `component/` | the extension point: every role's contract (`base.py`) apart from its shipped implementations, and the door a component enters by |
| `workspace/` | what a project keeps between commands (`registry`, `declarations`, `run_definition`) |
| `run/` | a run's life: `preflight/` (facts, checks, freeze, verdict) · `engine/` (the loop, events, stages named for the method they call) · `assemble` · `batch` · `recording` |
| `report/` | metrics and the report composed from a finished record |

Two guards keep it that way: the CLI imports only `vqapr.public` and the application layer, and no
two modules share a file name except `base.py`. `docs/vqapr-architecture.md` is the map.

## The account multiplies its own holdings (record `276`)

`Account.mark(state, prices)` values what the state holds; `domain/valuation.py` only chooses the
prices (a fresh row, a carried last price with the instant it was observed, or none). The stateless
`ValuationService` is gone. Every record is identical to what 0.15.0 wrote for the same inputs.

## The loop speaks discrete-event simulation (record `278`)

A run's schedule produces the events a model is called at; the execution table produces the market
events. The names say so now: `schedule:`, `ScheduledEvent`, `Clock.SCHEDULE`, `call.event_id`.

## One author surface (record `279`)

`vqapr.authoring` is removed. Everything an author writes against is in `vqapr.public`, aliased once:

```python
from vqapr import public as vq


class Momentum(vq.StrategyModel):
    def decide(self, call):
        ...
```

## Migrating a 0.15.0 tree

- **Every run declaration:** `agenda:` is `schedule:` — the same keys underneath (`every`, `at`,
  `from`/`to`, `on`, `days_from`). A declaration or a stored `.vqapr/workspace.yaml` that still says
  `agenda:` is refused with this fix; register the runs again.
- **Every component:** `from vqapr import authoring as va` → `from vqapr import public as vq`, and
  `va.X` → `vq.X`. `from vqapr.authoring import X` → `from vqapr.public import X`. A component's bytes
  change, so its fingerprint does: register it again.
- **Inside `decide`/`compute`/`observe`:** `call.evaluation_time` → `call.at`, `call.occurrence_id` →
  `call.event_id`.
- **Python callers:** `vqapr.public.preflight_run` → `vqapr.public.freeze`; `result.occurrences` →
  `result.events`; `RunAgenda`/`FrozenAgenda`/`OperationOccurrence` → `RunSchedule`/`FrozenSchedule`/
  `ScheduledEvent`; `Clock.STRATEGY` → `Clock.SCHEDULE`.
- **Run records:** a record written before 0.16.0 (schema v1) is refused with a fix — run it again
  with `vqapr run`; `vqapr rm` removes the old one. Nothing translates an old record.
- **CLI JSON:** keys that said `occurrences`/`occurrence_id` say `events`/`event_id`.
- **Installed skills** describe the old names; install them again (`vqapr skill install --force`).
- **Internal modules moved.** Only `vqapr.public` is a supported import; code that reached into
  `vqapr.flow`, `vqapr.project`, `vqapr.extension` or `vqapr.exchange` finds them in `run`, `workspace`
  and `component`.

## Validation

- `test_all` (`uv run python -m pytest tests/ -q -m ""`) on the stamped tree: **1,797 passed**,
  5 skipped (214 s; 1,794 at 0.15.0). All nine showcases exit 0 (`show_003` by hand on `data/DW`).
- Records: every campaign milestone M2–M10 held the showcase digest identical to the campaign baseline
  (81 entries). M11 changes the JSON records by design — schema v2, the `schedule` block, and new
  fingerprints for the rewritten showcase components; with the fingerprints stripped, **all 46
  showcase tables are identical** to 0.15.0's. The baseline is re-recorded for 0.16.0 and `--check`
  reads **83/83** entries identical.
- `uv run ruff check src/` (now with `A005`): clean. `uv run pyright`: 0 errors.
- `scripts/record_shipped_skills.py --check`: every shipped skill recorded for 0.16.0.
- The wheel and sdist are built from the tagged commit (`uv build`); neither carries tests,
  experiments, showcases or caches, and a wheel rebuilt from the sdist has the same files. The wheel
  installs into fresh Python 3.12.13 and 3.13.12 environments (duckdb 1.5.5 on 3.13) and passes the
  import and `vqapr --help` smoke checks. 3.14 is declared (`<3.15`) and **not verified on this
  release**: no 3.14 interpreter is installed on the release host.
