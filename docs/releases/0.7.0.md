# vqapr 0.7.0 — breaking

Released 2026-09-08 from `develop`. Records `170`–`173`. Every change below is on the agent-facing
surface: the JSON envelope, the declaration document, `vqapr.public`, and the sample. An agent or
script written against 0.6.0 has to be re-pointed; the sections say where.

## 1. Every refusal says who must act, where it was, and what happened (record `171`)

**The envelope's failure entry changed shape.** Keys, in order: `code`, `status`, `source`,
`requirement`, `observed`, `fix`, `cause`, `examples`, `example_total`. `explain` is gone. The
top level lost `family`; it carries `stage`, `mutation`, `retry_precondition`, `correlation_id`,
`failures`, `error` (and `detail` when a diagnostics file was also written).

- **`status`** is an HTTP number and is what to branch on first. 4xx: the submission is wrong,
  fix it before retrying — `400` invalid shape, `404` named but not there, `409` conflict with
  what is registered, `412` precondition of running does not hold (the `check` judgments),
  `422` the user's code cannot be called or returned something unusable, `423` locked. 5xx: the
  submission is fine, look at what ran — `500` the framework itself (file it upstream), `502` the
  user's own code raised, `503` the machine (file, disk). Handle an unknown `code` by its status.
- **`stage`** is a closed set: `usage`, `open`, `read`, `register`, `lookup`, `remove`, `write`,
  `load`, `check`, `freeze`, `run`, `record`. The free-form stage strings (`dataset.register.
  schema`, `preflight.account`, ...) are gone.
- **`cause`** is on every failure: `type`, `message`, `where` (`file:line (function)`),
  `origin` (`"user"` or `"framework"`), `traceback` — the whole text Python prints, never cut.
  A refusal raised without an exception still names the framework line that decided.
- **Every code was renamed** to `<subject>.<detail>`: `dataset.register.schema.field_missing`
  → `dataset.field_missing`, `check.lookback.uncovered` → `lookback.uncovered`,
  `workspace.dataset.lookup.missing` → `dataset.unregistered`, and so on. The complete old→new
  table with each code's stage and status is in `docs/implementations/171-*.md`. The skill's
  recovery sections are now one per status (`### Recovering from: 404 missing`).
- An exception nobody classified is no longer `stage: "unhandled", failures: []`: it is one
  failure, `code: "unhandled"`, status `500` or `502` by whose frame raised it, traceback in
  `cause`.
- `vqapr check`: `blocked` holds judgments that could not answer, as failures with a cause;
  phases never reached are listed under a new `skipped` key.
- `vqapr.public` exports `Status` and `Stage`.

## 2. A dataset declares its field types (record `173`, issue `088`)

- `datasets.<id>.field_types:` is **required** in a declaration document and in
  `DatasetRegistration.of(...)`. A sibling map of `fields`, one entry per exposed field, from the
  closed set `TIMESTAMP_TZ`, `DATE`, `INTEGER`, `DOUBLE`, `VARCHAR`, `BOOLEAN`. Registration
  compares the declaration with the parquet once and refuses a mismatch by name
  (`dataset.field_type_mismatch`, 400).
- **`DECIMAL` is not a field type.** A parquet column of `decimal128` is refused at registration
  (`dataset.field_decimal`); cast to `DOUBLE` while preparing the file. A model receives the
  declared type. A DataModel's output value fields must be declarable too
  (`datamodel.output.field_type`, 422). Execution-input prices may still be DECIMAL: a venue
  price is converted once at the money boundary and never reaches a model.
- A 0.6.0 workspace entry without `field_types` is quarantined until re-registered
  (`dataset.field_types_undeclared`). `vqapr new dataset` emits `field_types:` with the list.

## 3. `vqapr.public` lost the doors that skipped conformance, and some names nothing reached (record `170`)

- `component_ref` and `register_component` are gone. Register components through
  `register_strategy_model`, `register_data_model`, `register_constraint`, `register_exchange`
  (each returns the `ComponentRef` and proves conformance first) or through `vqapr register`.
- Deleted, tests-only or unreachable: `FillBatch.total_commission` / `total_tax` /
  `cost_by_kind` (the report computes cost by kind from the fill table), `listings.rules_view`,
  `ExecutionHorizon.at_or_before`, `OperationAgenda.from_occurrences` (a wall time that does
  not exist or occurs twice on a day is refused), `RunStateRepository.accept_no_decision` /
  `accept_intent`, `capture_live_memory` / `restore_live_memory`, `RunRecordLive.holder` (read
  `claim.pid`), `record.table_types`, `DuckDbObservationStore.query` (use `query_many`),
  `FrozenRun.physical_source_guarantee`.
- Report fields nobody read were removed from `StrategyReport` / `RunReport`:
  `annualized_mean_return`, the `Book` means (`mean_held`, `mean_gross_exposure`,
  `mean_net_exposure`, `mean_cash_share`) and `top_five_share`, `periods_positive`,
  `residual_pnl`, `positions_scored`, `median_periods`, `annualized_active_return`,
  `cumulative_active_return`. `tracking_error`, `information_ratio`, `mean_gap` and the
  headline's `cost_share_of_mean_nav_per_year` stay.
- `src/vqapr/extension/templates/` (five READMEs describing flags that did not exist) is gone.

## 4. The sample journey has a door (record `172`)

`vqapr new sample --out DIR` writes a complete, runnable journey: a five-day reversal strategy,
a venue, a synthetic ten-name panel over 735 real KRX sessions (codes `K000001`.., names and
prices made up — **not market data**, and it says so in `panel.json` and `README.md`), and
`sample.yaml`, the one declaration registering all of it. Then `vqapr register DIR/sample.yaml`,
`vqapr check sample-run`, `vqapr run sample-run`. The panel ships in the wheel (~370 KB);
nothing builds it on the user's machine. The old `vqapr.agent.sample.journey` module and the
warehouse-built panel are gone.

## Also in this release (not breaking)

- `vqapr run <id> --strategy typo` is a bounded refusal (`argument.value_invalid`, 400) instead
  of `stage: unhandled`; a datamodel refused inside a `--jobs` worker comes back as its own
  `VqaprError` (it pickles now) instead of an unpickling `TypeError`.
- One implementation where there were several: `Failure.as_dict()`, `JUDGMENT_CODES` published
  by `flow/judgments.py`, one request-validation loop for both venue profiles, one Pearson
  (`analysis.signal.correlation`; two identical return series correlate at exactly 1).
- The refusal-code baseline is a set per status, no line numbers; `uv run vulture` prints
  nothing.
- The datamodel scaffold `vqapr new datamodel` emits returns its value as `float`, so the
  unedited file runs under the DOUBLE-only rule of §2 (record `174`).

## Migrating a 0.6.0 agent or script

1. Branch on `failures[i]["status"]` first; drop any handling of `family` and `explain`.
2. Re-point every code you match on using the table in `docs/implementations/171-*.md`; the
   `stage` values you compared against are now the closed set above.
3. Add `field_types:` to every dataset declaration; cast decimal parquet columns to `DOUBLE`.
4. Replace `component_ref` + `register_component` with the `register_*` door for the kind.
5. When a 5xx arrives, read `cause.origin`: `"user"` means your own file (`cause.where` names
   the line); `"framework"` means quote `cause` whole in an upstream issue.
