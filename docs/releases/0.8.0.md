# vqapr 0.8.0 — breaking

Released 2026-09-08 from `develop`. Records `170`–`189`.

**0.7.0 was stamped but never tagged.** Its notes (`docs/releases/0.7.0.md`) are an accurate
account of records `170`–`180` and still the place to read about the refusal envelope, declared
field types, the sample door and the nine skills — **every one of those changes ships here**. Read
that file first if you are coming from 0.6.0; this file adds records `181`–`189`, the
component/event-loop campaign, on top of it.

The campaign changed four things an agent or a script can see: what a venue's `execute` is
handed, how a venue table is registered and priced, the `execution_input.*` refusal family, and
every run identity.

## 1. The venue table is a dataset, and the run picks the price (record `185`)

**`execution_inputs:` is retired.** `Workspace.open` refuses a document that still carries it,
naming this record and where the fill went. A venue table is now registered like any other
dataset, with one declared role:

```yaml
datasets:
  krx-daily:
    grain: instrument_instant        # required for an execution role
    execution:
      is_tradable: tradable          # must be BOOLEAN; declared, never derived
```

and the **run** says which of that dataset's numeric fields it trades at:

```yaml
runs:
  my-run:
    execution:
      dataset: krx-daily
      fill: {selector: same_day, at: "15:20", timezone: Asia/Seoul, trade_price: close}
```

The same table now fills one run at the close and another at the open with **no second
registration** — which is what the old shape forced, because the price lived inside it.
`exchange` and `execution` are declared together or not at all; a datamodel run declares neither.
The frozen identity hashes the dataset id and the fill, so an open-fill run and a close-fill run
over one table are two runs.

**Gone:** `register_execution_input`, `ExecutionInputRegistration`, `workspace.execution()`,
`workspace.execution_inputs`, the `execution-input` template of `vqapr new`. `SECTIONS` is
`instruments, datasets, components, runs`.

**New refusals, and a renamed family.** The `execution_input.*` codes are gone. Branch on these:

| gone | now |
|---|---|
| `execution_input.unregistered`, `.registered`, `.source_conflict`, `.reference_invalid` | (the section no longer exists) |
| `execution_input.field_type`, `.key_duplicate`, `.key_null`, `.price_invalid`, `.price_type` | `execution_table.field_type`, `.key_duplicate`, `.key_null`, `.price_invalid`, `.price_type` |
| — | `dataset.execution_no_price` — an execution role with no numeric field to bind |
| — | `dataset.execution_tradable_not_boolean` — the flag column is not BOOLEAN |
| — | `execution.dataset_has_no_role` — the run names a plain dataset |
| — | `execution.price_not_a_field` — `trade_price` is not a field the dataset carries |

`runs.<id>.execution.fill.selector` is judged as a closed set: a wrong value is
`declaration.value_not_permitted` naming both members, not a pydantic line inside `run_invalid`.

## 2. A venue is a Component and is handed a call (record `184`)

`Exchange.execute` took three positional arguments, and the framework reached into the instance
to plant the project's roster (`object.__setattr__(venue, "_registry", ...)`) because the
signature was not the framework's to change. It now takes one value:

```python
class MyVenue(AcademicExchange):
    def execute(self, call: ExecutionCall) -> FillBatch:
        # call.at, call.orders, call.account, call.snapshot, call.rules
```

`call.rules` is the venue's `ExchangeRulesView` already bound to the project's roster, so a
fill's category and its cost come from the project's answer rather than a venue's copy of it, and
the venue stores nothing the run handed it. **Any custom venue must be re-pointed.**

`Exchange` is a `Component` like the other three roles: it carries `memory` the run restores
before `execute` and commits with that fill's account commit. A profile that was a frozen
dataclass is a plain one now — a frozen instance could not receive memory.

## 3. Every run identity changes (record `182`)

The agenda no longer carries a role or a provenance. `FrozenAgenda.encoded()` folds the zone and
the local instants and nothing else, so **every strategy and datamodel identity differs from
0.7.0's**. This is a deliberate break: a datamodel run's agenda used to freeze as
`STRATEGY_CALLBACK` and fold that name into the identity of a run that never had a callback.
Existing records are not migrated. `OperationRole` is gone from `vqapr.public`.

## 4. `vqapr.public` — what moved

| gone | new |
|---|---|
| `register_execution_input` | `ExecutionRole`, `ExecutionTable` |
| `ExecutionInputRegistration` | `RunExecution`, `RunFill` |
| `OperationRole` | `Component`, `ExecutionCall` |
| — | `CrossSection`, `Series` (record `183`) |

`Grain` now comes from `vqapr.domain.shapes` rather than `vqapr.data.datasets`; the export itself
is unchanged, so only a direct internal import breaks. Internal module paths moved a great deal in
record `188` — `flow/record.py` became the `record/` package, `evidence/` was dissolved, and
`flow/` split into `strategy/`, `datamodel/` and `declaration/`. `vqapr.public` is the supported
surface and absorbed all of it.

## 5. Authored values are strict (record `187`)

`DatasetInput`, `AccountHistoryInput`, `ConstraintBounds`, `Hold`, `Rebalance`,
`ConstraintFinding`, the three lookbacks, `DataRequirement`, `Budget`, `AccountSnapshot` and
`TradeRule` are pydantic models with `strict=True`. A wrong type is refused rather than coerced:
`RowsLookback(True)` and `RowsLookback("3")` no longer pass as a count of 1 and of 3. Every
message the hand-written checks carried is kept as a validator, so a refusal that named its
numbers still names them.

## Also in this release (not breaking)

- **The four authored kinds share one base** (record `181`). `DataModel`, `StrategyModel`,
  `Constraint` and `Exchange` are all `Component`: they declare their reads with `inputs()`, are
  handed a bounded view at one instant, carry `memory`, and return one judgment. A `Constraint`
  may now remember — *"out after three breaches"* is a rule that counts — and its memory is
  restored before `project` and before `monitor` and committed with each publication.
- **The loop is an `EventLoop`** (record `182`): typed events, a merge of the frozen schedule
  with the due items a callback mints, and one walk shared by a strategy run and a datamodel run.
- **The shapes data takes have names** (record `183`): `CrossSection` (instrument → value at one
  instant) and `Series` (instant → value for one instrument) below everything, with `Grain`.
- **pyright is a gate at zero** (record `186`), and the guards a type checker made redundant are
  gone (record `187`).
- **The dead-code pass is silent again** (record `189`).

## Migrating a 0.7.0 tree

1. **The declaration document.** Delete the `execution_inputs:` section. Register that table under
   `datasets:` with `grain: instrument_instant` and an `execution: {is_tradable: <field>}` role,
   then give each run an `execution: {dataset:, fill: {..., trade_price:}}`. `Workspace.open`
   refuses the old shape by name, so you cannot run against a half-migrated document.
2. **Any custom venue.** Change `execute` to take one `ExecutionCall`; read `call.orders`,
   `call.account`, `call.snapshot` and `call.at`, and use `call.rules` instead of any roster the
   framework used to plant.
3. **Anything branching on `execution_input.*`.** Use the table in §1.
4. **Run identities.** Every id changes; re-run rather than expecting a record to match.
5. **Anything importing `vqapr.flow.record`, `vqapr.evidence`, `vqapr.flow.simulation` or
   `vqapr.flow.run`.** Import from `vqapr.public`.
